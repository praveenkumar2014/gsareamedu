# Data model

`users`: unique normalized email, password hash, role. `programs`: title, description, area, publication status. `leads`: name, email, message and status (NEW, CONTACTED or CLOSED). `enrollments`: user and program foreign keys with a unique pair. `audit_events`: optional actor, action, target identifier, timestamp. `login_attempts`: email-keyed failure count and lock expiry. `lessons`: program, title, plain-text content, order and publication status. `lesson_progress`: unique user/lesson completion record; application authorization checks enrolment and publication before inserting. UUIDs are generated in application code; timestamps are database-generated. Schema and authoritative constraints are in `apps/web/lib/schema.ts` and `drizzle/`. Relationships restrict deletion of enrolled users/programs; audit actor becomes null on deletion. Retention, consent, deletion and data export policy require owner decisions before production.
